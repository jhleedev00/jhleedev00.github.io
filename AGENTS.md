# Portfolio workflow

- Preserve existing user edits and confirmed project contribution boundaries.
- Use concise Korean bullet points and noun endings (구현, 적용, 유지, 처리) for visible portfolio descriptions, not narrative sentences.
- After requested changes, commit the scoped edits without asking again. Do not treat commit permission as unconditional permission to publish.
- Send both web and PDF verification results with the handoff. Clearly distinguish source checks from actual rendered verification; never call an unexported PDF verified.
- Check desktop and mobile web layouts, and export/render the current A4 PDF to check all pages when supported. If tools cannot export it, state that limitation and request the user's current PDF for visual verification.
- Follow LOCAL_VALIDATION.md's full-validation-before-push gate unless the user explicitly overrides it. Do not change deployment settings or bypass browser security restrictions to run verification.
- Keep source PPT/Canva documents unchanged unless explicitly requested.
